# Domain docs

This project uses a single-context layout: a root `GLOSSARY.md` and ADRs under `docs/adr/`.

Before exploring an area of the project, read `GLOSSARY.md` and relevant ADRs in `docs/adr/` when those files exist. Their absence needs no action; create them when domain terms or decisions are resolved.

Use the glossary's defined terms in issue titles, proposals, hypotheses, and tests. If a needed concept is missing, reconsider the name or record the gap for domain modeling.

If a proposed change conflicts with an ADR, identify the ADR and explain the conflict explicitly.
